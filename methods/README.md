# methods：基线方法与代表性方法

每个子文件夹是一个方法：
- `run.py`：该方法的预测函数；
- `README.md`：做法概括；
- `scores.json`：内部验证的汇总分数，以及 Kaggle 官方分数（`kaggle_private`、`kaggle_public` 等字段，取自 `results/kaggle_scores.csv`）。
- `rows.csv`：内部验证中每个被预测行的误差（`err` 列是该行的 RMSE），不是预测值。预测值见提交文件。

所有方法共用 `harness.py`（验证协议、计分、导出）和 `code/` 中的模块，所以分数可以直接比较。

```bash
python 10_blend/run.py
```

运行内部验证，共 34 折（协议 A 4 折 + V1 30 折）。

```bash
python 10_blend/run.py --export
```

用全部训练行训练，导出按 Kaggle 顺序排列的提交文件到 `results/methods/10_blend/`。

**防泄漏**：被隐藏的行（验证目标或测试行）在交给方法之前会被设为 NaN。方法只要读取了这些行，输出就会是 NaN，框架随即报错。当前 12 个方法和已移除的 3 个方法全部通过。另外，通过 `10_blend/run.py --export` 生成的文件与已提交的 blend_v1 最大差异为 1e-7，只是 CSV 的舍入误差。

## 验证协议
- **A**：依次留出一种 T/NK 细胞，只保留它的 15 个锚点和 2 个对照（模拟 B/Myeloid 的情况；CD8+ 只有 13 个锚点），预测它的官方测试化合物。四种细胞都计入。
- **V1 / V1w**：在 B/Myeloid 上逐个留出锚点。V1w 只统计在来源细胞中响应较弱的锚点，大多数测试化合物属于这一类。
- **objective** = mean(V1w / 1.1625, A / 0.9402)，即相对 KRR v1（局部 KRR 的第一版，已归档）的值，KRR v1 = 1.000。所有指标都是越低越好。
- **口径变更（2026-11-16）**：此前协议 A 不计 CD8+（记为 A15，objective 中除以 0.9894）。各方法的选择和调参是按旧口径做的；所有 `scores.json` 已按现行口径从 `rows.csv` 重算，主要模型的排序不变。`results/` 下的历史实验脚本和 `nn_v2_lab/README.md` 的选择记录保留旧口径。

## 内部验证与官方分数是否一致
加上已归档的 KRR v1（官方 0.830）和 LGT（官方 0.901），共 14 个方法。按内部 objective 排序和按官方 private 排序：
- **前 4 名完全一致**：blend < 底座 + I2 < 底座 + I1 + I2 < 底座 + I1。
- **最大的差别是局部 KRR（05a）**：内部排第 6（0.990），官方排第 5（0.799），超过了神经网络底座（0.813）和联合 KRR（0.823）。
- **几个最弱的基线之间**也有小幅交换。
- Spearman 秩相关为 0.94。

所以内部验证对大多数方法的排序是可靠的；但它会低估"强化合物幅度"上的优势，I2 幅度头和局部 KRR 都受此影响。原因见 `Question 2/`（标签生成研究，官方流程）。

## 局部 KRR、联合 KRR 与神经网络
局部 KRR 只用目标细胞的 15 个锚点作标签，神经网络则用全部可见行。联合 KRR（05b）用全部可见行和与神经网络相同的输入，只把 MLP 换成核岭回归。对比结果如下：
- **联合使用数据**：相对 KRR v1 有帮助，objective 从 1.000 降到 0.995，官方从 0.830 降到 0.823。但调好的局部 KRR（05a，v2 配置）官方 0.799，反而好于联合 KRR。
- **学习器**：同样的输入和数据下，联合 KRR 到神经网络底座，0.995 降到 0.957，官方从 0.823 降到 0.813。
- **强化合物**：局部 KRR 在 V1 上最好（1.731）。这正是它官方表现好、并被选进 blend 的原因。

详见 `05b_krr_joint/README.md` 和 `results/krr_joint_study/`。

## 从表中能看到什么
- **大多数测试化合物响应很弱**，全零和中位数这类基线已相当于 objective 1.05。用均值就会被少数强毒性化合物带偏（01）。
- **把来源细胞的偏移整体搬过来不行**（04 比 02、03 都差），迁移量必须收缩。KRR 正是在这一点上取得了第一个真正的提升（05a）。
- **神经网络底座大幅改善弱锚点（V1w）**，但对强化合物的幅度预测不足。幅度头 I2 补上了这一点，也是官方分数提升的主要来源。
- **blend 在协议 A 上最好**，V1w 接近最好，objective 最低，官方分数也最好。
- **内部验证会低估幅度建模的作用**：I2 相对底座，内部好 1.6%，官方好 7.4%。原因见 `Question 2/`（标签生成研究，官方流程）。

## 已移除的方法
**规则**：一个方法如果比某个保留的、更简单的方法复杂，而在 A、V1w、V1 三项上全都更差，且不是最终模型的组成部分，就移除。

| 方法 | 被谁全面超过 | A | V1w | V1 | objective | 官方 private / public |
|---|---|---:|---:|---:|---:|---|
| LGT（原实现 L3，PCA 子空间分块门控） | 按 A15 时为 03；按现行协议 A 略好于 03 | 1.054 | 1.277 | 2.344 | 1.109 | 0.901 / 0.669 |
| 底座 + 第 4 名收缩后处理 | 06 底座 | 0.952 | 1.100 | 2.117 | 0.980 | — |

- **LGT 与全零几乎一样**（官方 0.901 对 0.902）。原因是截距用了锚点均值，而且匹配来源时丢掉了 Alvocidib、Oprozomib 这两个关键锚点。按现行协议 A，它不再被 03 全面超过，但这一实现缺陷不变，所以仍留在存档中。官方分数来自按正确顺序重排后的 `L3_kaggle_ids.csv`；最早按错误行序提交的 1.201 无效。
- **KRR v1 也已归档**：`05a_krr_local` 现在用的是 KRR v2 配置，v1 就移到了存档，并不是被其他方法全面超过。v1 仍是 objective 的基准（1.000），它的分数是 A 0.940、V1w 1.163、V1 1.890，官方 0.830 / 0.604。
- **三者的代码和分数**都保存在 `archive/methods_removed/`，仍可运行。

**例外**：
- **01 目标细胞均值**：也被全零全面超过，但它几乎没有复杂度，作为最朴素的参照基线保留。
- **09 底座 + I1 + I2**：objective 略逊于 08，但它是 blend 的组成部分，弱锚点上也最好，因此保留。

## nn_v2 系列（2026-11-13 新增）

`code/nn_v2.py` 是 `code/nn.py` 的副本，改动都做成开关，开关全关时与 `nn.py` 逐行误差相同。原有的 06–10 号方法没有改动。
